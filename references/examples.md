# 例子

这些只是体裁和处理方式的示意，不是固定句式。

## 会议碎片

输入：

```text
小林：登录页复杂
阿杰：先减必填项
下周看数据
```

可以写成：

```markdown
# 周三登录页讨论

小林说登录页复杂，阿杰建议先减必填项。下周看数据，再决定删哪些。

- 待办：看登录数据
- 待办：列出必填项
```

这里保留了人名、顺序和未决状态，没有补一个团队共识。

## 技术 README

输入里如果写着“可能在某些系统失败”“请把复现步骤发来”，就把这类协作入口保留下来。不要为了让文章更完整，把所有失败都改成“兼容性良好”。

## 极端改写

可以把冗长的背景删掉，把决定、失败条件和下一步前置；不能为了显得不整齐而破坏代码、链接、步骤或接口。
